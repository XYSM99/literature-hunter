# 受限访问的降级路径

境外站点常因 CDN 区域策略、 robots、反爬而对特定地区 IP 封锁。**本文件只使用匿名公开手段**，不涉及任何账号、登录、付费绕过。

## 一、先判断是哪种拦

| 表现 | 大概率原因 | 下一步 |
|---|---|---|
| 403 + `Access Denied` + CDN 错误排行（如 edgesuite / cloudfront 签名） | CDN 区域拦截 | 依次尝试下面 L1 → L3 |
| 404 | 路径错误或已下架 | 找目录页 / 编号存档 |
| 000 / 超时 | 目标不可达或被中间网络丢弃 | 换协议、换镜像；不要反复重试同一 URL |
| 200 但返回 HTML 却不是文件 | 跳转到了封面页或验证页 | 看 `content_type` 是否为 `application/pdf` |

## 二、降级路径（按序尝试，命中即停）

### L1 — 换协议：https → http

不少政府与机构站点对 https 的 CDN 策略比对 http 更严格。**同一 URL 把 https 换成 http，常常立刻放行**，速度与支持 Range 的能力都正常。这是成本最低、最先尝试的一步。

```bash
curl -sL --max-time 60 -o x.pdf -w "%{http_code}/%{size_download}/%{content_type}\n" \
     "http://example.org/docs/manual_2024.pdf"
```

若 http 自动 301 跳回 https 且被拦，改用禁止重定向 + 手动跟随的方式试探。

### L2 — 带完整浏览器请求头 + 小范围请求

加 UA、Accept、Accept-Language；并用 `Range` 请求先探再取。**Range 请求常被完整 GET 拦而不放行的规则放行**，同时也是判断文件存在性的低成本手段。

```bash
curl -sL --max-time 45 -o probe.bin -w "%{http_code}/%{content_type}\n" \
     -r 0-99 -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/126 Safari/537.36" \
     "http://example.org/docs/manual_2024.pdf"
```

返回 `206` 且 `content_type: application/pdf` → 可用。

### L3 — 换入口：编号存档 / 镜像 / 年鉴拷贝

1. **机构知识库**：搜文档标题 + 年份，找永久编号记录，用 `${库}/view/<编号>/...` 形式取原文
2. **第三方恢复镜像**：部分公共卫生站点存在社区镜像（把被删除的政府页面整体复制），先查该站是否收录了目标文件
3. **合作机构转载**：大型医学中心、州一级卫生厅常把同一份手册挂在自己域名下，用文件名搜索即可找到
4. **堆叠层面**：多个域名交替试，避免单点失败

### L4 — 官方 API / 结构化服务

一些机构提供公开 REST/JSON 接口（如出版质量批量接口），比爬 HTML 稳定。检索「<机构名> API + 文档」确认是否存在，存在则优先使用。

## 三、拿到文件后必须做的事

### 完整性校验

PDF 未下载完也会有完整文件头（`%PDF-1.7`）**但缺少文件尾**。检查尾部最后一个 marker：

```bash
tail -c 8 file.pdf | xxd | head -1   # 期望出现 %EOF
```

### 断点续传补齐

```bash
# 循环续传直到出现 %%EOF
for i in 1 2 3 4 5; do
  curl -sL --max-time 300 -C - -o out.pdf "<URL>"
  tail -c 8 out.pdf | grep -qa "EOF" && { echo COMPLETE; break; }
done
```

**⚠️ 实测踩坑：续传不是万能的。** 遇到不支持字节范围的服务器，`curl -C -` 会直接报错退出
（`exit 33：HTTP server doesn't seem to support byte ranges`），文件永远停在残缺状态，
循环再多次也是原地踏步。`fetch_docs.py` 已在 2026-10 的修订中处理了这点：
每轮比对文件大小，只要没有增长就判定续传无效，自动去掉 `-C -` 整份重下。

判断服务器是否支持续传，看响应状态码即可：

```bash
curl -sL -r 0-99 -o /dev/null -w "%{http_code}\n" "<URL>"
# 206 = 支持续传；200 = 忽略 Range，只能整份重下；403/405/501 = 明确拒绝
```

**⚠️ 第二个坑：追加写必须先确认 206。** 发了 `Range` 却被服务器忽略时，它返回的是 200 全量内容；
此时若仍以追加模式写入，残缺文件后面会接上一整份完整内容——文件变大却依旧损坏。
正确做法是检查状态码：不是 206 就从头覆盖写。

### 元信息核对

```bash
python scripts/pdf_probe.py out.pdf
```

确认页数、大小、首页标题（首页常含版本年份），对照站点标称值是否一致。

## 四、已知不可靠手段（避免浪费时间）

- 公共 CORS 代理服务：多数对二进制与大文件支持差，或已关停
- 网页时光机类站：有时整站不可达，或只存了旧快照且文件不全
- 反复重试同一 https URL：CDN 拦截通常不会因重试改变策略

## 五、抓取礼仪（硬性）

- **串行**：一次只下一个文件，禁止并发批量
- **留间隔**：连续请求之间间隔 1–3 秒
- **限速**：单个文件超时设 60–300 秒，遇到超时就换路径而不是硬跑
- **先探后取**：用 100 字节 Range 请求确认，再拉全文，避免大流量浪费
- **尊重 robots 与服务条款**：文中技法只用于公开、可合法下载的资料；遇付费墙与登录拦截应停止并转向其他合法来源
